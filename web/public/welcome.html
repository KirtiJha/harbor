The problem

localhost turns into a crowded harbor

Every project brings a dev server, an API, a database and a watcher. They pile up on ports you never chose, and the tools to see them are a wall of lsof output.

Error: listen EADDRINUSE: address already in use :::5173

“Port already in use”, by what?

Something holds the port. Finding out what means lsof -i :5173, reading a pid, then ps to see what that pid is.

VITE ready → http://localhost:5174/ Port 5173 is in use, trying another one…

Apps quietly move ports

Vite and Next take the next free port without asking. The bookmark on :5173 now opens a different project.

$ kill 55958 [vite] restarting… listening on :5174

Killing the wrong process

The pid on the port is a child. Its parent (make dev, npm run dev, a reloader) starts it again.

node 62826 *:4700 (LISTEN) # reachable from the café Wi-Fi

Exposed and forgotten

Servers bound to all interfaces are open to your network. Week-old servers keep holding memory nobody uses.

How it works

One loop, from sockets to your screen

A small local server reads the machine every two seconds, makes sense of what it finds and streams the picture to your browser. The flow below is live: hover a box.

  1. Read the machine: every listening TCP socket (lsof) and the whole process table (ps). About 0.2 s.
  2. Understand each one: its project (package.json, pyproject, git), its framework (Vite, Next, Uvicorn, Postgres…) and the app that launched it.
  3. Ask each server over HTTP for its status, page title and response time, so “node” becomes “Shop web · 200 · 7 ms”.
  4. Decide: what opened or closed, what is idle, what moved off its port, what is exposed to the network, what is safe to stop.
  5. Stream the picture to the browser as it changes (server-sent events), with every action behind a session token.
  6. Run your saved apps with their output captured, conflicts resolved and crashes restarted, and remember notes and settings.
  7. Route http://shop.localhost:7475 to wherever Shop is listening today, websockets included.
Stop whole app

Stops what started it, not just the process on the port

The process on the port is rarely the one you meant. Harbor walks up the process tree through launchers (make, npm, shells running a command, reloaders) and stops at your terminal, editor or agent. It never goes past them.

Then it asks politely (SIGTERM), waits a few seconds, and forces only the processes still running (SIGKILL). Desktop apps and macOS services need you to type the port number first, and Harbor never uses sudo.

Stable names

Bookmarks that keep working when the port changes

Give an app a short name and open http://name.localhost:7475. Harbor sends it to whatever port the app is on now, websockets and hot reload included. When Shop lands on :5174 because Docs site got :5173 first, the bookmark still works.

Browsers send *.localhost to your own machine. No DNS setup, no hosts file, no certificates.

Features

Everything you reach for when localhost gets busy

📡

Live port map

Every listening port, grouped by project, with framework, page title, HTTP status, uptime, connections, and CPU and memory sparklines.

🧭

Knows the project

Reads package.json, pyproject and git to name each port after its project, instead of “node” or “Python”.

🛑

Stop the right thing

Stop a process or the whole app tree, one at a time or several at once, gracefully first and by force only if needed.

🚀

Saved apps

Command, folder and port saved once. Start, stop and restart in one click, with live coloured logs and clickable URLs.

🧩

Groups

Put backend and frontend in a group and start or stop the whole thing with one click.

⚔️

Conflicts handled first

Before starting, Harbor shows who holds the port. Take the next free one (it sets PORT and fills {port}) or take it over.

🌙

Forgotten servers

Dev servers with no connections and no CPU for hours are flagged idle. Stop them all in one click and get the memory back.

🔗

Stable names

name.localhost:7475 follows an app to whichever port it is on, websockets included.

📱

Phone testing

Network-exposed servers show their Wi-Fi URL. Others are marked local-only, so you know what the café can reach.

🔔

Watch and notify

Watch a port, and Harbor shows a banner, a toast and a desktop notification when it goes down, with a button to start it again.

🔍

Find projects

Scans a folder for npm, pnpm and yarn scripts, Makefile targets, Django, FastAPI, Flask and Streamlit apps, and Compose files, ready to add.

⌨️

Keyboard first

⌘K palette (type a port number to jump to it), / to search, j/k to move, o to open, x to stop, p to pin, space to select.

🐳

Docker aware

Published container ports show the container name and image, with a docker stop button.

🕰

History

An activity timeline, a per-port history, response-time sparklines and an uptime count for every server.

📦

Share setups

Export your apps to JSON, and import a teammate's to get the same one-click setup.

🖥

Starts with your Mac

harbor service install runs it at login through launchd. uninstall removes it.

Command line

The same answers in your terminal

Every dashboard question has a short command. who tells you what is on a port, kill --app stops it properly, and free finds a port you can use.

  • harbor ls listening ports (--all, --json)
  • harbor who 5173 command, folder, app, HTTP answer
  • harbor kill 5173 --app stop the whole app
  • harbor free 3000 -n 5 next free ports
  • harbor service install start at login

        Safe by design
        
A process killer you can trust

      

      

        
127.0.0.1 only
Harbor never listens on your network.

        
No DNS rebinding
It answers only requests addressed to its own localhost port.

        
Session token
Every change needs a token only Harbor's own page can read, so other sites can't send it commands.

        
Guard rails
It can't stop itself, other users' processes, or anything outside what it shows. Desktop apps and macOS services need you to type the port number.

        
No sudo, no cloud
Your user's processes only. State stays in ~/.harbor.

        
Zero dependencies
The backend is the Python standard library, so there's nothing to install or audit.
